## Настоящие Ollama, MCP и локальный Outline

`help-regression.txt`/`.log`: интерактивные `/help` и `/exit` отработали с настоящей Ollama, существующим индексом документации и MCP. Ответ содержит источники README, ветку main и commit Outline.

`installed-doctor.log`: собран wheel и выполнена обычная установка **без editable** в `/tmp/outline-assistant-install.HfAmal`. Импорт модуля подтверждён из `site-packages`, а не из исходников проекта. Запуск `doctor --review` из `/tmp` с абсолютным config успешно проверил обе модели, MCP, Git, документацию, каталоги и чтение настоящего GitHub API. Это проверка установки, **не зарегистрированный Actions runner**.

Модели:

- `bge-m3:latest`, digest `7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab`;
- `qwen3:8b`, digest `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`.

`run_local.py` копирует 11 настоящих файлов Outline (6 документов и 5 TS-файлов) во временный Git-репозиторий. Все изменения/ветки создаются там. Анализ использует настоящие BGE-M3/Qwen3, MCP stdio, Git diff и RAG; **метаданные PR обслуживает локальная HTTP-фикстура**, публикация отключена. Это ограниченная выборка, не полный индекс Outline и не GitHub Actions.

Итоговый прогон: `local-results.json`, `local-run.log`, четыре пары `review.json`/`review.md`:

| Сценарий | Ожидание | Наблюдение |
|---|---|---|
| `obvious_bug` | `shallowEqual` ошибочно возвращает true при разных длинах | Один обоснованный high bug на изменённой строке 15 |
| `breaking_contract` | Удаление string из типа `naturalSortBy` ломает существующие вызовы | Один high bug на строке 30, верно указана ошибка TypeScript; ссылки замечания остались на определении функции, без прямой ссылки на переданные вызовы |
| `safe_refactor` | Вынесение `a === b` в const не меняет поведение | **Ложный medium bug** о вызывающем коде/«путанице»; семантическое ожидание не пройдено |
| `docs_only` | Исправление грамматики не вносит технической проблемы | Замечаний нет |

Все четыре анализа технически завершились (`complete`), но это означает обработку diff, **не истинность замечаний**. В contract явно указано ограничение поиска символов. В первом сценарии рассчитаны 105 уникальных embeddings; далее для изменённых снимков — 2, 3 и 1 новых, с повторным использованием 113/114/114 векторов. Все RAG-источники принадлежат head соответствующего сценария.

Первоначальные результаты сохранены в `initial/` и `second/`: там модель также давала ненужные рекомендации и ложное замечание на грамматику. После этих наблюдений уточнён prompt и исправлен реальный дефект поиска, который останавливался на импорте. Повторный прогон не скрывает оставшееся ложное срабатывание. Валидация проверяет структуру, SHA, существование путей/строк и ID; она не доказывает семантическую причинность. Нужна оценка человеком, автоматического merge/approve нет.

SHA учебных коммитов существуют только в удалённом после проверки временном репозитории. GitHub-ссылки в этих учебных отчётах поэтому **не открываются**; для настоящего PR код формирует ссылки на его опубликованные SHA.

Исходный Outline остался на `main`, `ebffdb7f7f1f966aa05739f7140e1aec09209475`, с чистым status. Скрипт сравнил до/после HEAD, ветку, status и хеши всех 11 прочитанных файлов (`outline_unchanged=true`).

## Настоящий GitHub и оставшееся внедрение

Read-only API подтвердил публичный fork `metalice80/outline_t`, parent `outline/outline`, default branch `main`; список PR был пуст. `GITHUB_TOKEN`/`GH_TOKEN` отсутствуют; endpoint runners вернул 401. Права записи, настройки Actions и наличие online runner **не подтверждены**. SHA `actions/upload-artifact` v4 проверен через GitHub API.

Workflow подготовлен в `integrations/github/ai-review.yml` и перенесён в отдельный checkout `.review-work/outline_t/.github/workflows/ai-review.yml`. В checkout только этот новый файл; commit/push не выполнялись. В исходный Outline ничего не добавлялось. Полные команды находятся в [руководстве](../../docs/AI_REVIEW.md).

Остались внешние шаги:

1. Получить поручение на push workflow в fork, регистрацию/запуск runner и создание учебного PR. Предыдущее разрешение push касалось ассистента в другом репозитории.
2. Установить проверенный пакет в постоянный доверенный каталог вне PR, настроить абсолютные пути и Ollama, зарегистрировать runner с `ai-review` и запустить `run.sh`.
3. Включить Actions, задать `AI_REVIEW_BIN`, `AI_REVIEW_CONFIG`, `AI_REVIEW_HOME`, проверить фактические права `contents: read`/`pull-requests: write`; разместить workflow в main fork, затем разрешить публикацию в доверенном config.
4. Создать PR владельца из ветки того же fork; проверить настоящий run, отчёты и комментарий. Добавить второй commit, проверить новый SHA и обновление того же comment ID, отмену старого run и запрет публикации stale-отчёта.

**Полный внешний цикл PR → runner → комментарий → обновление ещё не проверен.** Реальной публикации комментария, регистрации runner и включения workflow не было. Сохранённые фикстуры не являются доказательством этих действий.
